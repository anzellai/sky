## Migration shape

The PR-11 spec: delete `inferTypeFromGoString` (the lossy Go-string→T.Type reverse mapper) and migrate `lookupLambdaType`'s return type from `Maybe T.Type` to `Maybe GoType`.

Mechanical steps:

1. Change `_lc_lambdaTypes :: Map String T.Type` to `Map String GoType` (or a Maybe GoType-flavoured variant).
2. Change both `lookupLambdaType` signatures (Compile + LC versions).
3. At the writer (line 8112): drop `inferTypeFromGoString`; the caller already has the typed `gty :: String` — but post-PR-3's parseGoType, that string can become a `GoType` directly.
4. At each of the 5 caller sites: read the GoType and use it for the originally-intended purpose. Each site uses T.Type fields differently:
   - 5593 routes typed-ident dispatch.
   - 8849 recovers a typed arg for the next emission.
   - 12637 destructures `TLambda` to peel args.
   - 14134 surfaces a type for inferExprType's recovery.
   - 14868 feeds a typed-coerce decision.
5. Each caller's downstream T.Type-shape consumer needs a GoType equivalent. Some are mechanical (e.g., GoType has `GoFunc from to` for TLambda), some are not (T.Type has `TType home name args` carrying canonical-module identity that GoType collapses to `GoNamed`).
6. Update LowerCtxCascadeSpec for the new type.
7. Run probe-TCO-1..7 to verify TCO emission is unchanged (lesson 4 gate).
8. RendererParitySpec stays green (lesson 2).

## Risk assessment

Architecturally this is moderate-sized; the migration is mechanical at most call sites, but some (e.g., line 12637's TLambda destructure) need careful inspection because GoType's structural shape differs from T.Type's. Each caller's behaviour change is observable through emitted Go.

Pre-mortem lesson 4 makes this PR critical: it's the first PR where a continue-block byte diff is a real bug. The TCO probes are the gate.
