# Cause H — typed tuples — discovery: not a dual-alias close

**Branch:** `feat/v0.17-fully-typed-codegen`
**Status:** ATTEMPTED + REVERTED this tick.

## Hypothesis (wrong)

Cause H seemed structurally identical to C13/C14/C15. The runtime
already parameterises tuples (`type T2[A, B any] struct {...}`) and
`SkyTuple2 = T2[any, any]` is the back-compat alias. So emitting
`rt.T2[string, int]` at sig slots should be transparent — same as
emitting `rt.SkyCmd_T[Msg]` over `rt.SkyCmd`.

## Why it doesn't work

Unlike C13/C14/C15, the typed tuple sibling is NOT a type alias —
it's a DIFFERENT generic instantiation:

```go
type T2[A, B any] struct { V0 A; V1 B }
type SkyTuple2 = T2[any, any]  // alias, same type-identity

// But:
rt.T2[string, int]  // DIFFERENT type-identity from rt.T2[any, any]
```

Go's reflect-based `rt.Coerce` can't bridge `T2[any,any]` →
`T2[string,int]` because they're distinct generic instantiations,
not aliased synonyms. Probe-H reproduces:

```
rt.Coerce: expected rt.T2[string,int], got rt.T2[interface {},interface {}] ({Alice 30})
```

The `makePair "Alice" 30` literal constructs `SkyTuple2{V0:"Alice", V1:30}`
(== `T2[any,any]`), then the typed-return slot wants `T2[string,int]`.
Mismatch.

## What closing Cause H actually requires

Tuple literal lowering (`Can.Tuple`) must ALSO emit the typed form
when LowerCtx carries concrete element types:

```haskell
-- current
GoStructLit "rt.SkyTuple2" [("V0", v0), ("V1", v1)]

-- required for Cause H
case lookupTupleElementTypes ctx region of
  Just [tA, tB] ->
    GoStructLit ("rt.T2[" ++ goTypeOf tA ++ "," ++ goTypeOf tB ++ "]")
                 [("V0", coerceToA v0), ("V1", coerceToB v1)]
  Nothing ->
    GoStructLit "rt.SkyTuple2" [...]
```

Same logic across `Can.Tuple` (literal) AND `Can.Lambda` /
`Can.Pattern` (destructure) so the round-trip stays consistent.

Plus: `Basics.fstT[A, B](t SkyTuple2) A` and `Basics.sndT` accept
the alias form — they'd need overloads (or generic-renaming) to
accept `T2[A, B]` instances.

## Recommendation

Defer to a dedicated multi-PR session with LowerCtx propagation
through tuple literal lowering as the primary work. This is the
SAME pattern as the deferred typed-pipeline work that was carried
through Phase η planning.

Cause H stays in the "PARTIAL/deferred" status alongside
Cause B (CSI key widening) — both need invasive LowerCtx
threading.

## What's NOT typed-tuple but adjacent

Sky's tuples already work correctly today — `(name, age)` typed
as `(String, Int)` round-trips fine, just via the alias form
(SkyTuple2 = T2[any, any]) instead of the typed form
(T2[string, int]). This is a quality refinement, not a
correctness fix.
