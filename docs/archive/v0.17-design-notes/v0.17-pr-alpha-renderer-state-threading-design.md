# v0.17 PR-α — Renderer-state threading design

**Branch:** `feat/v0.17-fully-typed-codegen`
**Target master plan step:** Consolidated post-Phase α architectural close.
**Subsumes:** PR-6c (`globalCurrentDepModule` line 7730 reader),
PR-7 (`globalAnonRecords`), PR-8 (`scopeStateRef` LowerCtx holder).
**Estimated budget:** 4-6 sessions (largest single PR in v0.17).
**Status:** design crystallised; incremental execution.

## TL;DR

Three load-bearing IORefs in `Sky.Build.Compile.hs` carry renderer
state across deeply-nested lazy-thunk call stacks. Each was
introduced to dodge a specific lazy-CAF caching pathology, not as
architectural debt. The defuse requires changing the renderer's
*shape* — moving from "renderer pure function reads ambient IORef"
to "renderer explicitly takes a ctx argument" — while preserving
the lazy-evaluation order that the IORef pattern relies on for
correctness.

## The three targets

| IORef | Sites | Read/Write count | Risk |
|---|---|---|---|
| `globalCurrentDepModule` | line 640, 3372/3375 (write), 7730 (read) | 2 writes, 1 read | Lowest |
| `globalAnonRecords` | line 197-199, 17746 (write), 4570 (read) | 1 write, 1 read | Medium (producer-consumer) |
| `scopeStateRef` | line 448-451 + ~12 wrapper sites + ~13 reader sites | 12 writes, 13 reads | Highest (already LowerCtx-shaped but ambient) |

## Architectural pattern (current)

```haskell
-- Writer (sentinel-style, in generateDeclsForDepScoped):
setSentinel = GoIr.GoDeclRaw (unsafePerformIO $ do
    writeIORef globalCurrentDepModule (Just modName)
    return "")
clearSentinel = GoIr.GoDeclRaw (unsafePerformIO $ do
    writeIORef globalCurrentDepModule Nothing
    return "")

-- Reader (deep inside typeStrWithAliasesRegBounded, line 7730):
T.TType _ "Html" [arg]
    | (case arg of { T.TVar _ -> False; _ -> True })
    , isNothing (unsafePerformIO (readIORef globalCurrentDepModule)) ->
        "Std_Html_Html_T[" ++ rec arg ++ "]"
T.TType _ "Html" _ -> "Std_Html_Html"
```

The sentinel emits an empty-string GoDecl that runs the IORef
write during PRINT-time (not construction-time), so the writes
happen between the previous dep's print and the next dep's print
— exactly when the reader needs them. Threading the value via
function argument breaks this because the construction time
(when typeStrWithAliasesRegBounded would receive the argument)
and the print time are different lazy-evaluation phases.

## Architectural pattern (target)

Replace the print-time IORef bracketing with construction-time
ctx threading + per-decl pre-rendered strings.

```haskell
-- Each call site that today calls typeStrWithAliasesReg ty becomes:
typeStrWithAliasesRegScoped (ctx :: RendererScope) ty

-- RendererScope is the new pure value carrying the dep-mode hint:
data RendererScope = RendererScope
    { _rs_depModule :: !(Maybe String)
    , _rs_anonRecords :: !(Map String (Map String T.FieldType))
    }

-- generateDeclsForDepScoped sets the scope ONCE before constructing
-- the dep's [GoDecl] tree; the tree's lazy thunks carry the scope
-- captured at construction time:
generateDeclsForDepScoped :: String -> Can.Module -> String -> [GoIr.GoDecl]
generateDeclsForDepScoped modName canMod modPrefix =
    let scope = RendererScope { _rs_depModule = Just modName, ... }
    in generateDeclsForDep scope canMod modPrefix
```

## Why this is multi-session

The renderer family (`typeStrWithAliasesReg{,Bounded}`,
`solvedTypeToGo{,Bounded,Typed,PreserveTVars}`,
`safeReturnTypeFullBounded`, `safeReturnTypeBootstrap`,
`safeReturnTypePureBounded`, `inferredSigSkyToGo`,
`splitInferredSigWithReg`, …) has ~10+ entry points with ~150+
call sites scattered across the lowerer. Threading
`RendererScope` requires:

1. **Widen each entry point's signature** to take `RendererScope`.
2. **Update every caller** to pass the scope.
3. **Propagate via recursive helpers** (the `rec` function in each
   renderer's `where` clause).
4. **Audit lazy-vs-strict positions** at every print-time hook
   (e.g. `GoDeclRaw`'s thunk) to ensure scope is captured at the
   right time.
5. **Test gates** at every checkpoint: cabal-test, example-sweep
   26/26, verify-ui-showcase.

Realistic per-session breakdown:

| Session | Scope | Deliverable |
|---|---|---|
| 1 | `RendererScope` type + scaffolding | New type, no behavior change. Cabal-test green. |
| 2 | Widen `typeStrWithAliasesReg{,Bounded}` + close `globalCurrentDepModule` reader | Line 7730 reads from scope. IORef still present as fallback. Sweep 26/26. |
| 3 | Widen `solvedTypeToGo` family + downstream consumers | All renderers ctx-aware. Sweep 26/26. |
| 4 | Migrate `globalAnonRecords` writer + reader via scope | Producer-consumer pattern threaded. Sweep 26/26. |
| 5 | Merge with `scopeStateRef`'s LowerCtx pattern (the two scope records become one) | Single LowerCtx threaded everywhere. Sweep 26/26. |
| 6 | Delete IORef definitions + sentinel patterns | Cleanup. Final cabal-test + sweep + verify-ui-showcase + cli. |

## Pre-mortem (lessons carried from PR-6, PR-7, PR-8 analyses)

* **Lesson 1**: lazy-CAF caching breaks naive threading. The
  scope must be captured at the lazy-thunk's construction time
  (when the calling function builds the thunk), not at the
  thunk's force time.
* **Lesson 2**: parallel renderer passes (per dep module) write
  to `globalAnonRecords` concurrently via `atomicModifyIORef'`.
  Threading must preserve the merge-at-orchestrator semantic.
* **Lesson 3**: `Sky.Build.TailCallOpt` reads
  `LowerCtx._lc_enclosingTypeParams` via the scopeStateRef
  snapshot. Wide-grep audit required at PR-α-5 boundary.
* **Lesson 4**: The 16-skychess close (commit f4392835) used the
  inverse pattern — pre-seed `globalUnionNames` IORef BEFORE
  HM-time read. That worked because HM had a clear sync point
  (after `splitInferredSigWithReg`); the renderer family has no
  such single sync point.
