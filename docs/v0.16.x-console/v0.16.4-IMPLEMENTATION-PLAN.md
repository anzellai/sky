## Implementation chunks (sequential, each ships to main on completion)

### Chunk 1 — CLI scaffolding + skeleton daemon (THIS SESSION)
- Add `sky console serve` sub-command in `app/Main.hs`
- New `Sky.Console.Hub` module that contains a `runHubServer` entry point
- Parse flags: `--port` (default 4000), `--data-dir` (default `./skyhub-data`),
  `--auth token|app|off`, `--tls-cert`, `--tls-key`
- Skeleton: bind port, print "listening", block on signal handler
- No receivers / no storage / no UI yet — just the daemon shell
- Verifies the CLI + flag plumbing works before adding real surface

### Chunk 2 — OTLP HTTP receiver
- Wire `go.opentelemetry.io/collector/receiver/otlpreceiver` (HTTP path)
- Endpoints: `POST /v1/traces`, `POST /v1/metrics`, `POST /v1/logs`
- Accept both `application/x-protobuf` (preferred) and `application/json`
- Token auth via `Authorization: Bearer <SKY_CONSOLE_HUB_TOKEN>`
- 4 MiB payload cap (configurable via `SKY_CONSOLE_HUB_MAX_PAYLOAD`)
- Drop telemetry through a channel into Chunk 3's writer
- End of chunk: the v0.16.1 HubExporter (already in `rt/exporter_spool.go`)
  pushes successfully to a running `sky console serve`

### Chunk 3 — SQLite hot store
- Open `<data-dir>/console-hot.db` (WAL mode)
- Reuse the schema from embedded mode (`runtime-go/rt/telemetry/persist.go`)
  with one ADDED column: `service_name` (resource attribute key)
- Index `service_name + time` on every table
- Write goroutine drains the receiver's channel, batched per 200 ms or
  128 entries
- Hourly prune goroutine: drop rows older than 24 h
- End of chunk: pushed data is queryable by `service_name`

### Chunk 4 — Reuse console_app UI for single-service view
- Mount the existing `runtime-go/rt/console_app/` at hub's `/` HTTP path
- Backing store: not in-memory telemetry.Store but a SQLite-backed
  read-through implementation (`hubStore`)
- Service selector header element — exposes a Sky.Live cookie / query
  param that filters every query
- For now ONLY single-service mode (selector = "first service in store")
- End of chunk: pushing from a Sky.Live app via HubExporter and opening
  the hub's web UI shows that app's logs/traces/metrics

### Chunk 5 — Multi-service dashboard (`/services/all` view)
- Header service selector mode "all" (per HUB-UI.md)
- Overview tab: per-service stats cards in a left scroller; aggregate
  charts on the right
- Status pill: green/yellow/red based on recent error rate
- Sparklines (Std.Ui.Chart.sparkline) for req/s, p95, error rate
- Wire SSE: `Sub.every 5000` per-service status refresh, `Sub.every 1500`
  for the selected service's charts
- End of chunk: hub UI shows 2+ services side-by-side, sparkline live-updating

### Chunk 6 — Multi-service Requests/Errors/Logs/Traces tabs
- Requests tab: virtual-scroll list, click-to-expand spans, status filter
- Errors tab: heatmap + list view, drill to trace
- Logs tab: SSE tail, level filter chips, FTS5 substring search
- Traces tab: span-tree expander
- Each tab respects the service selector + time-range picker
- End of chunk: full HUB-UI.md feature set on the hub

### Chunk 7 — Auth `app` mode + tenant scoping
- Hub itself becomes a Sky.Live app that consumes its OWN consoleAuth
- `Identity.claims.tenant` filters every store query by `service_name LIKE '<tenant>-%'`
- Single-tenant `token` mode still the default
- Login form for `app` mode (HKDF-derived cookie like the embedded console)
- End of chunk: SkyDeploy-as-hub deploy works (one hub, N tenants)

## What `complete and useful` means for v0.16.4

A user can:
1. Run `sky console serve --port 4000 --data-dir ./hub-data --auth token`.
2. Set `SKY_CONSOLE_HUB=http://hub-host:4000` + `SKY_CONSOLE_HUB_TOKEN=<secret>`
   in each of their Sky.Live apps.
3. See ALL those apps' logs/traces/metrics in one dashboard at
   http://hub-host:4000/.
4. Drill from a multi-service overview down to one app's requests,
   errors, logs.
5. Run this on a single e2-small VM. SkyDeploy can ALSO use it as a
   tenant-scoped hub for its customers (Chunk 7).

If a user CAN'T do all five end-to-end, v0.16.4 isn't ready to tag.
