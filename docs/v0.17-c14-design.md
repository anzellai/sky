# C14 — typed Std.Ui call-site emission (Cause C closure)

**Branch:** `feat/v0.17-fully-typed-codegen`
**Predecessor:** C13 dual-alias scaffolding (`056ec7fb`, `9986d6aa`, `4d677c8f`)
**Cause:** [C in cause-status](v0.17-cause-status-2026-06-13.md) — Std.Ui kernel polymorphism erased

## Goal

When the emitted Go return type would today be bare `Std_Ui_Element`
and the Sky-side type carries a concrete (non-TVar) type argument,
emit the typed sibling form `Std_Ui_Element_T[<arg>]` instead.

`view : Int -> Element Msg` →
- today: `func view(count int) Std_Ui_Element`
- after C14: `func view(count int) Std_Ui_Element_T[Main_Msg]`

## The emission gate

The single edit lands in `typeStrWithAliasesReg` at
[Compile.hs:7051](../src/Sky/Build/Compile.hs#L7051) — the
`T.TType home name _` catch-all arm that currently drops type args
for parametric Sky ADTs.

```haskell
T.TType home name args
  | hasDualAlias home name
  , Just renderedArg <- concreteArg recAliases fieldIdx tvarMap args ->
      let goName = mangleHome home ++ "_" ++ name
      in goName ++ "_T[" ++ renderedArg ++ "]"
  | otherwise ->
      -- existing path: emit bare goName, drop args
      ...
```

Where:
- `hasDualAlias home name` — known set of polymorphic Sky ADTs that
  emit the `_T[T1 any]` sibling per C13. Initially: Std.Ui's
  `Element` and `Attribute`. Expand later via a side-table populated
  by `generateUnion` so this stays in sync.
- `concreteArg recAliases fieldIdx tvarMap args` — recurses
  through `typeStrWithAliasesReg`; returns `Nothing` if ANY arg is
  a TVar (we can't emit `Std_Ui_Element_T[any]` — that's the bare
  `Std_Ui_Element` collapse anyway).

## Probe-C tightening (post-flip)

After C14 ships, tighten probe-C-stdui-msg-typed:

```
MUST_CONTAIN func view(count int) Std_Ui_Element_T[Main_Msg]
```

Currently locked to `func view(count int)` prefix; flipping to the
typed sibling form is the regression fence.

## Adversary checks BEFORE implementing

1. **Callers**: who consumes `view`'s return value? `main` in
   probe-C: `let _ = view 0`. Discarded — no type issue.
   For real Sky.Live apps, `view` reaches `Live.app cfg`'s `view`
   field which is typed `func(any) any`. The shift from
   `Std_Ui_Element` to `Std_Ui_Element_T[Msg]` must not break that
   assignment. Both resolve to `rt.SkyADT` at runtime (alias
   transparency), so Go's type identity holds.

2. **Cross-module use**: a downstream module importing `view` sees
   the new return type. Does the importer's emitted Go declare
   `Main_Msg` so `Std_Ui_Element_T[Main_Msg]` resolves?
   The dep-module path's lowering would need the typed sibling
   alias for `Main` ADTs registered in dep ldr. Probably reach for
   `_T` only when the arg's home is the entry-module or a known
   dep. Otherwise stay bare.

3. **Stdlib emission**: kernels like `Std_Ui_row` return
   `Std_Ui_Element` today. Their return type doesn't carry a TVar
   in the call site (the Ui kernel is generic — the Sky-side type
   inference resolved it). If C14 flips kernel return types too,
   then `Std_Ui_row`'s emit becomes
   `Std_Ui_Element_T[Msg]`. But `Std_Ui_row` is defined in
   `Sky.Core.Ui` / `Std.Ui` stdlib — its declared sig has TVar
   `msg`, so the existing path returns "any" / drops the TVar.
   Verify: stdlib calls don't flip via this gate (TVar arg → no
   concrete → bare emit).

4. **Cmd.perform interaction**: `Cmd.perform task toMsg` where
   `toMsg : Result a b -> Msg`. The return-type slot here is
   `Cmd` (already opaque per `T.TType _ "Cmd" _ -> "rt.SkyCmd"`
   in typeStrWithAliasesReg). Out of scope.

5. **wrapTypedReturn / coerceReturnExprT coverage**: the body's
   return expression today coerces to bare `Std_Ui_Element`. If
   the sig changes to `Std_Ui_Element_T[Main_Msg]` but the body
   still produces `Std_Ui_Element`, Go's alias transparency makes
   them interchangeable — no body change needed.
