## Architectural principle (user's guidance, 2026-06-07)

> "Use the tracking of Sky code as HM has the guarantee of
> usage — so types are fully known if used or called. We need
> to just defer the Go code gen when the actual usage is in
> Sky code, otherwise staying generic is actually fine."

**Translation**: When Sky's HM solver tells us that `cfg`'s
type matches the callee's expected parameter type at a call
site, we should emit `editorBody(cfg)` (raw, no cast) and let
Go's call-site type inference pin the callee's generic param.
Only emit a cast when HM says they DON'T match. The existing
parametric-alias shortcircuit in `coerceArg` (lines
9736-9740 path a, 9742-9745 path b — `src/Sky/Build/Compile.hs`)
IS this design. The bug is that it doesn't fire reliably.

### Why path (b) shortcircuit in coerceArg still misses

`coerceArg`'s path (b) at line 9742-9745:
```haskell
| Just targetBase <- parametricAliasBase ty
, Just src <- mSrc
, Just aliasName <- aliasBaseFromCanExpr src
, aliasName ++ "_R" == targetBase
    = e
```

For Editor.view body's `editorBody cfg`:
- `ty = "Editor_Cfg_R[any]"` (after substituteOnly's blind erasure)
- `targetBase = parametricAliasBase ty = Just "Editor_Cfg_R"`
- `src = Just (Can.VarLocal "cfg")`
- `aliasBaseFromCanExpr src` → `inferExprType solved src` →
  returns whatever `_stEnv["cfg"]` has — likely
  `T.TAlias _ "Cfg" [T.TVar fresh-var] _` for the unsolved msg

Then `aliasBaseFromCanExpr` (`Compile.hs:10123`):
```haskell
case inferExprType solved src of
    Just (T.TAlias homeMod aliasName _ _) ->
        ... check Set.member aliasName _cg_recordAliases ...
    _ -> Nothing
```

Pattern matches on `T.TAlias`. So if the returned type IS a
TAlias, this should hit. The check at line 10143-10147 verifies
the alias is a RECORD alias (`_cg_recordAliases` set
membership). "Editor_Cfg" should be in that set.

**Diagnostic needed**: add Debug.Trace inside
`aliasBaseFromCanExpr` for the deep IIFE case. Does it return
`Just "Editor_Cfg"` or `Nothing`?

If `Just "Editor_Cfg"`: path (b) fires; cast should be skipped.
But we see the cast emitted → path (b) ISN'T firing.

So either:
- `mSrc` is `Nothing` at the call site (caller doesn't pass it)
- `aliasBaseFromCanExpr` returns Nothing (something failing)
- The path (b) guard fails on `aliasName ++ "_R" == targetBase`
- Control flow goes through a DIFFERENT coerceArg call (not the
  one this branch covers)
