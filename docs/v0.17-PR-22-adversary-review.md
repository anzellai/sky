# PR-22 Adversary Review

Adversary against the Architect's plan at
`docs/v0.17-PR-22-bulk-execution-plan.md`. Goal: catch flaws now,
not after burning 2-3 sessions on bisects.

---

## Fatal flaws (must address before any code)

### F1. Two-surface API breaks parity tests by construction

§3 declares `mapSkyTypeToGo` (pure) and `mapSkyTypeToGoIO` (IO) as
divergent at TRecord arms:

> "TRecord arms emit GoStruct inline as today." (pure)
> "Routes TRecord arms through mcAnonRecRegister so the IORef
> write happens lazily." (IO)

But §5's verification gate is:

> "`solvedTypeToGoBounded 64 Set.empty t == renderGoType
> defaultRenderEnv (mapSkyTypeToGo ctx t)` for every t in the
> corpus."

Legacy `solvedTypeToGoBounded` ALWAYS emits `Anon_R_<hash>` for
unmatched records (`Compile.hs:17446` calls `synthAnonRecordName`,
which itself runs `unsafePerformIO` at line 18390 to register).
The pure `mapSkyTypeToGo` emits `GoStruct` inline. **These will
NEVER match on any TRecord input.** The "parity oracle" is
deceptive: green tests don't certify production behaviour because
production uses the IO surface and tests use the pure one.

This is the same `unsafePerformIO`-hiding-IO-in-pure-code
pattern that motivated R1 in the risk register. **The plan
walks into it.**

**Required:** the parity test MUST exercise the IO surface
(unsafePerformIO-wrap or run in IO Spec). Pure `mapSkyTypeToGo`
on a TRecord should either be deleted or hard-error so test
authors can't accidentally take the silent path.

### F2. `synthAnonRecordName` is already `unsafePerformIO` — the "callback in MappingContext" doesn't change semantics, only deceives readers

`Compile.hs:18390` shows the current generator IS pure-typed:
`synthAnonRecordName :: Map String FieldType -> String` with
`unsafePerformIO . atomicModifyIORef'` inside. Wrapping it as
`mcAnonRecRegister :: ... -> IO String` in MappingContext (§1,
line 48) gives the SAME thunked side effect, but now hidden
behind a field of a record passed through every type-mapping
recursion.

The plan claims this is safer because production runs in IO. It
isn't. It is identical from the runtime's perspective AND it
introduces a new lazy-evaluation hazard: a parity test that
builds a context with `defaultMappingContext` (whose callback
returns `"Anon_R_unbound"` per §1 line 53) **silently produces
wrong output**. No type error fires. No runtime error fires.
The output just diverges.

**Required:** the sentinel `Anon_R_unbound` must `error` (Haskell
`error`), not return a string. Any code path that hits it on a
TRecord is a bug that should crash loudly in tests, not slip
through with cosmetic divergence.

### F3. `SKY_RENDERER_DIFF=1` runs the differential AFTER pipeline migration — too late to catch σ_go divergences

§5 says:

> "every call to `mapSkyTypeToGoIO` ALSO calls
> `solvedTypeToGoBounded` and `Debug.Trace.traceM` on mismatch"

The differential fires at the RENDER call site, AFTER
monomorphisation has already substituted σ_go. But R4 in the risk
register acknowledges σ_go is load-bearing for Go-generic
instantiation — and σ_go is BUILT from `solvedTypeToGoPreserveTVars`
output BEFORE it reaches the typed renderer for the lowered
expression.

**If the pipeline produces `Module_Foo_R[any]` where legacy
produced `Module_Foo_R[T1]`, σ_go silently substitutes the wrong
thing.** Downstream `mapSkyTypeToGo` is then called on an ALREADY-
DIVERGENT type tree. The differential check passes (both
renderers agree on the post-substitution tree). The Go build
fails with `Foo_R[any]` not satisfying `Foo_R[Msg]` at the call
site. Hours of bisecting.

**Required:** the differential gate must fire BEFORE σ_go
substitution AND on the input `T.Type` (not the lowered tree),
covering EVERY caller's input pre-monomorphisation. This means
instrumenting `solveModule` / `monomorphise`, not just
`mapSkyTypeToGoIO`.

## Serious concerns (must mitigate)

### S1. Anon-record hash stability is not specified

§2-#8 says `mapRecordTypeIO` calls `mcAnonRecRegister ctx
fields`. Legacy `synthAnonRecordName` (`Compile.hs:18382-18389`)
computes:

```
sorted   = Map.toAscList fields
typeStr  = concatMap (\(_, FieldType _ ty) -> show ty) sorted
nameTag  = intercalate "_" (map sanitiseField (map fst sorted))
nameStr  = "Anon_R_" ++ nameTag ++ "__" ++ shortHash (nameTag ++ typeStr)
```

The hash inputs include `show ty` of the SKY-side `T.Type`. If
the pipeline ever calls registration with a `T.Type` whose Sky
representation has been touched by typed-codegen intermediaries
(e.g. `T.Hoisted` / `T.Filled` unwrapping), `show ty` produces a
different string → different hash → `Anon_R_xyz` vs
`Anon_R_abc` → "undefined: Anon_R_xyz" at Go build.

**Required:** S5 (`AnonRecordRegistrySpec`) must include a
fixture where the same record shape arrives via both raw and
TAlias-unfolded paths. The hashes MUST match. If they don't, the
generator needs canonicalisation BEFORE hashing.

### S2. 32-caller bulk migration assumes mechanical sed-replacements suffice

§4 S6's migration table is mechanical:

> "Use a single sed-friendly mechanical rewrite"

But the call sites vary: some run in pure code (`Compile.hs:12189`
uses `solvedTypeToGoPreserveTVars` inside a `go` recursion on
TLambda), some in IO. The rewrite replaces `solvedTypeToGo t` →
`renderGoType ... <$> mapSkyTypeToGoIO ctx t` which is `IO String`
— that doesn't fit in a pure context without `unsafePerformIO`,
which the project bans except in narrow IORef wrappers.

**Required:** classify all 32 sites by Pure / IO before S6 starts.
Pure-context sites must use `mapSkyTypeToGo` + accept the missing
anon-record registration (and have a non-anon input invariant
documented), or be lifted to IO. Don't mechanise across the two
classes.

### S3. `git revert HEAD` rollback ignores cross-slice coupling

§4 claims rollback = `git revert HEAD`, but:

- S1 adds 6 fields to `MappingContext` (consumed by no one yet).
- S2-S5 consume them.
- S6 callers depend on S1-S5's pipeline behaviour.

Reverting S6c when S6d has shipped (sites depend on the pipeline
shape) leaves dangling type errors. Reverting S2 with S6
partially shipped detonates the runtime divergence.

**Required:** S6 subslices must be self-contained (no
divergence-creating arms within S2-S5 should ship until S6a-d
exercise them). Practically: ship S6a tied to one divergence
arm at a time. Bundle S2 arm A with S6a callers, S2 arm B with
S6b callers. Don't let pipeline arms exist unexercised across
slice boundaries.

### S4. `solvedTypeToGoPreserveTVarsBounded` is a DIFFERENT renderer, not a policy flip

The Architect maps `solvedTypeToGoPreserveTVars` → `mcTVarsToAny
= False`. But the legacy implementation (`Compile.hs:17040-17065`)
has a custom TVar arm:

```haskell
T.TVar name
    | isGenericTypeParam name -> name   -- preserves USER NAME
    | otherwise              -> "any"
```

`isGenericTypeParam` discriminates by name shape. The pipeline's
`mcTVarsToAny = False` arm in `Type.hs:830-832` is:

```haskell
T.TVar name
    | mcTVarsToAny ctx -> GoAny
    | otherwise        -> GoTypeVar (goTypeParam name)
```

`goTypeParam` may CANONICALISE the name (e.g. user-written `msg`
→ canonical `T1`). Legacy preserves the exact user name. **σ_go
substitution keys are user-named TVars.** If the pipeline emits
canonical names, σ_go lookups miss and Go-generics break.

**Required:** S6c must add a fixture where the user-written TVar
name (e.g. `msg`) is preserved by the pipeline AT THE RENDER
STAGE. The plan's "5 monomorphisation fixtures" must include
the user-named TVar case explicitly, and `goTypeParam` must be
audited for non-identity rewrites.

### S5. `solvedTypeToGoViaPipelineFlat` adapter contradicts the "100% correctness" goal

§6 keeps the adapter shim "for one more release as a hard-coded
`mcTVarsToAny=True` adapter; flag for deletion in v0.18". But
this adapter at `Compile.hs:17287-17304` reads `getCgEnv` AT
CALL TIME (not at MappingContext construction):

> "let ctx = (GoType.buildMappingContext ... getCgEnv) { ... }"

That's an IORef read inside what looks pure. Mirrors exactly the
hazard the plan claims to fix. Either delete the adapter at S7
(force every call site to build its own context) or document
the IORef-read contract explicitly.

## Reasonable risks (accept and monitor)

### A1. Verification economics

The plan's 8.5-session estimate (§8) is OPTIMISTIC by ~50% for a
32-caller bulk migration with 5 cross-cutting concerns. Realistic
budget: 12-15 sessions. Accept; don't time-box S6 prematurely.

### A2. RuntimeMaps module extraction

S0's `Sky.Generate.Go.RuntimeMaps` extraction is mostly mechanical
(static `[(String,String)]` tables at `Compile.hs:6828, 6837`).
The risk that `splitGoMangledQualified` (FFI hyphen mangle) has
hidden deps on Compile.hs internals is low — it's a string
function. Accept and monitor.

### A3. `mcUnionNames` snapshot timing (Div #7)

The plan's mitigation (sanity assertion under
`SKY_DEBUG_UNION_SNAPSHOT=1`) is sufficient PROVIDED every
production `buildMappingContext` call site is downstream of
`Rec._cg_unionNames` being final. The `globalUnionNames`
write at `Compile.hs:4136` precedes most codegen. Accept.

## Required plan changes

- **§1 sentinel:** `mcAnonRecRegister` in `defaultMappingContext`
  must be `\_ -> error "anon-record reg called from pure ctx"`,
  not `pure "Anon_R_unbound"`.
- **§3 two-surface API:** delete the pure `mapRecordType` for
  TRecord, OR force it to error. Tests use the IO surface
  exclusively.
- **§5 differential gate:** instrument BEFORE σ_go substitution
  in `monomorphise`, not at the render call site. Add a
  pre-monomorphisation T.Type-input differential that compares
  the legacy and pipeline `solvedTypeToGoPreserveTVars` outputs
  on every type that flows into σ_go.
- **§4 slice S6:** classify all 32 sites Pure/IO before
  starting; subdivide by classification, not by mechanical
  count of 8. Bundle each S2-S5 pipeline arm with the S6 sites
  that exercise it — no unexercised arms across slice
  boundaries.
- **§5 anon-record fixture:** add the dual-path hash-stability
  case (same shape via raw + TAlias-unfolded paths must hash
  identical).
- **§6 adapter:** EITHER delete `solvedTypeToGoViaPipelineFlat`
  at S7 OR document that its `getCgEnv` IORef read is an
  intentional escape hatch — don't leave the contract
  ambiguous.
- **R4 fixtures:** include explicit user-named-TVar
  preservation fixture (`view : Cfg msg -> Element msg` with
  literal `"msg"` flowing through σ_go).
- **Timeline:** budget 12-15 sessions, not 8.5.

## What WOULD make me approve this plan

A revised plan that:

1. Deletes the pure TRecord path in §3 (or hard-errors on the
   sentinel) — no silent two-surface divergence.
2. Adds the pre-σ_go input-side differential gate in §5 (catches
   F3).
3. Couples each pipeline-arm slice (S2-S5) with the S6 callers
   that exercise it (no unexercised arms shipping across
   commits).
4. Adds the user-named-TVar preservation fixture AND the
   dual-path anon-record hash-stability fixture to
   RendererParitySpec PRE-S0.
5. Classifies all 32 callers Pure/IO in S0 deliverables; S6
   migration table updated accordingly.
6. Budget revised to 12-15 sessions with the user warned.

Without (1) + (2), this plan WILL detonate a runtime panic class
that no test catches, and we'll spend two sessions bisecting
before identifying the root cause. (3)-(6) are
session-economics tightening — the plan ships without them but
costs more sessions than estimated.
