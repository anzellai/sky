# Upgrading from v0.28 to v0.29.0

This page lists every change in v0.29.0 that can affect code or a deploy that
worked on v0.28.1. Each entry is one bullet: what changed, the old code, and the
new code.

- **Loud** changes stop the build. The error names the change.
- **Loud at run time** changes compile, but the program or the CLI stops with
  an error that names the change.
- **Silent** changes compile, but the program behaves differently.

The full story of each change is in `CHANGELOG.md` under v0.29.0.

## Loud (fails to compile, the error shows the fix)

### New stdlib names

- A bare name that two `exposing (..)` imports now both export is `[E1012]`
  ambiguous, and the error names both modules.
  - `Sky.Core.List` gains `map2`, `map3` and `unique`. `Sky.Core.Maybe`,
    `Sky.Core.Result`, `Sky.Core.Task`, `Sky.Core.Json.Decode` and
    `Std.Db.Decode` already export `map2` / `map3`; `Std.Db.Schema`,
    `Std.Db.Store` and `Std.Db.Table` export `unique`. A bare `map2 f a b`
    under two such `exposing (..)` imports -> `Maybe.map2 f a b`.
  - `Sky.Core.String` gains `uncons`, `foldl` and `foldr`. `Sky.Core.List`
    and `Sky.Core.Dict` already export `foldl` (List `foldr` too). A bare
    `foldl f acc xs` under `import Sky.Core.List exposing (..)` and
    `import Sky.Core.String exposing (..)` -> `List.foldl f acc xs`.
- `Sky.Core.Array` is a new module with Elm's names (`get`, `set`, `push`,
  `map`, `foldl`, …). It breaks no existing program; import it qualified:
  `import Sky.Core.Array as Array exposing (Array)`.

### Regex takes a compiled Regex

`Sky.Core.Regex` now has a type `Regex`. `Regex.fromString : String -> Result
Error Regex` is the only way to make one, and every other function takes the
compiled value instead of the pattern String. Before, each call compiled the
pattern again, and an invalid pattern silently matched nothing (`False`,
`Nothing`, `[]`, the input unchanged). Now an invalid pattern is an `Err` with
the RE2 error text, and a literal pattern is checked when the program compiles
(`[E2014]`, see `docs/errors/E2014-invalid-regex.md`).

Old code fails to compile with a type error whose hint names this section:
`Regex functions take a compiled Regex since v0.29.0`.

- `Regex.match p s` -> `Regex.contains re s` (`Regex.match` is still there and
  is the same function, but it takes a `Regex` too).
- `Regex.find p s`, `findAll`, `findMatch`, `findAllMatches`, `split` ->
  the same name with a `Regex` first.
- `Regex.replace p replacement s`, `Regex.replaceWith p f s` -> the same with a
  `Regex` first.

Before:

```elm
import Sky.Core.Regex as Regex

isCode : String -> Bool
isCode s =
    Regex.match "^[A-Z]{3}-\\d{4}$" s
```

After: compile the pattern once, at the top level, and use the value:

```elm
import Sky.Core.Regex as Regex exposing (Regex)

codeRe : Regex
codeRe =
    Regex.fromString """^[A-Z]{3}-\d{4}$"""
        |> Result.withDefault Regex.never

isCode : String -> Bool
isCode s =
    Regex.contains codeRe s
```

A literal pattern is checked when the program compiles, so
`Result.withDefault Regex.never` never gives `never` for it. For a pattern that
comes from outside (a setting, a user's search), handle the `Err`:

```elm
search : String -> List String -> Result Error (List String)
search pattern lines =
    Regex.fromString pattern
        |> Result.map (\re -> List.filter (Regex.contains re) lines)
```

Writing patterns: a triple-quoted string keeps a backslash (`"""\d+"""` is
`\d+`; a plain string needs `"\\d+"`). Inside one, `\\` is one backslash
(`"""\\d"""` is also `\d`) and `{{` opens an interpolation, so a literal `{{`
is written `\{{`. A single `{` (`\d{2,4}`) is kept. A `Regex` cannot be stored
with a `Codec` or in a session: store the pattern.

`import Sky.Core.Regex exposing (..)` now also exposes `contains` and
`fromString`. Beside `Sky.Core.String exposing (..)` (`contains`), or
`Sky.Core.Bytes`, `Sky.Core.Secret`, `Std.Decimal` or `Std.Money` with
`exposing (..)` (`fromString`), a bare use is `[E1012]`: qualify it
(`Regex.contains`, `String.contains`).

### A value defined in terms of itself

- A cycle of values is `[E1018]` BAD RECURSION. It used to pass `sky check`,
  then deadlock on the first read (top level) or fail `go build` (inside a
  `let`), so no working program is affected. The error names the cycle. See
  `docs/errors/E1018-value-cycle.md`.
  - Before: `a = b + 1` and `b = a * 2`.
  - After: give one of them a base value (`b = 2`), or a parameter when it
    really is a loop (`next _ = …`, called as `next ()`).

## Loud at run time (compiles, then stops with an error)

- None in this part of the release.

## Silent (compiles, behaves differently)

### Sky.Live sessions start fresh

- **What happens.** A `Dict` (and a `Set`) is now a persistent value,
  `rt.SkyDict[V]`, with a new stored form. A Sky.Live session kept in a
  SQLite, PostgreSQL or Redis session store by v0.28 whose model holds a
  `Dict` cannot be read by v0.29.0 (a `Set` could not be stored before
  v0.29.0, so no stored session holds one). The session is dropped whole:
  the runtime logs one line per session, for example
  `[sky.live] postgres: failed to decode session <id>: the stored session was
  written by an older Sky and holds a Dict or a Set, whose stored form
  changed in v0.29.0; it is dropped and the visitor starts a new session`,
  and the request is served as a new session (`init`). There is no panic and
  no half-read model.
- **Who is affected.** Apps with a persistent session store (`[live] store` /
  `SKY_LIVE_STORE` = `sqlite`, `postgres` or `redis`) whose `Model` holds a
  `Dict`, once, on the first request of each such session after
  the upgrade. Not affected: the memory store (it does not survive a restart
  anyway), a model without a `Dict`, and `App.withDurable`
  snapshots (they are JSON, and a Dict writes the same JSON as before).
- **What to do.** Nothing in code. A visitor with such a session sees a
  fresh page once after the deploy (signed-in state that lives only in the
  model is lost with it). To avoid surprise, deploy at a quiet time or tell
  users. To clear the old rows yourself, delete them from `sky_sessions`
  before the deploy.

### Other silent changes

- **Go code must not change a list it is given.** `x :: xs` is now amortised
  O(1): a list built by cons shares its memory with every older list it was
  built on. A Go function reached through FFI that sorts or writes a slice
  argument in place (`sort.Strings(names)`) now also changes those older
  lists. Copy first: `sorted := slices.Clone(names); sort.Strings(sorted)`.
  The rule is in `docs/ffi/boundary-philosophy.md`. Sky code cannot observe
  the sharing: Sky lists stay immutable values.
- **An old list keeps its block alive.** A short list kept for a long time (in
  a Sky.Live model, say) that was the tail of a large accumulator keeps the
  accumulator's memory alive. If a model holds such a tail, rebuild it
  (`List.map identity tail`) before you store it.
- **String kernels keep invalid UTF-8 bytes.** `String.slice`, `left`,
  `right`, `dropLeft` and `dropRight` return a substring of the input. An
  invalid UTF-8 byte inside the result is kept as it was; before, the rune
  round trip replaced it with U+FFFD. Valid text gives the same bytes as
  before, and every index still counts code points.
