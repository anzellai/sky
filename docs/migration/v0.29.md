# Upgrading from v0.28 to v0.29.0

This page lists every change in v0.29.0 that can affect code or a deploy that
worked on v0.28.1. Each entry is one bullet: what changed, the old code, and the
new code.

- **Loud** changes stop the build. The error names the change.
- **Loud at run time** changes compile, but the program or the CLI stops with
  an error that names the change.
- **Silent** changes compile, but the program behaves differently.

The full story of each change is in `CHANGELOG.md` under v0.29.0.

## Loud (fails to compile, the error shows the fix)

### New stdlib names

- A bare name that two `exposing (..)` imports now both export is `[E1012]`
  ambiguous, and the error names both modules.
  - `Sky.Core.List` gains `map2`, `map3` and `unique`. `Sky.Core.Maybe`,
    `Sky.Core.Result`, `Sky.Core.Task`, `Sky.Core.Json.Decode` and
    `Std.Db.Decode` already export `map2` / `map3`; `Std.Db.Schema`,
    `Std.Db.Store` and `Std.Db.Table` export `unique`. A bare `map2 f a b`
    under two such `exposing (..)` imports -> `Maybe.map2 f a b`.
  - `Sky.Core.String` gains `uncons`, `foldl` and `foldr`. `Sky.Core.List`
    and `Sky.Core.Dict` already export `foldl` (List `foldr` too). A bare
    `foldl f acc xs` under `import Sky.Core.List exposing (..)` and
    `import Sky.Core.String exposing (..)` -> `List.foldl f acc xs`.
- `Std.Codec` gains `zeroJson` (the JSON of a codec's zero value) and
  `fieldZeros` (the zero of each field of a record codec, which
  `Store.migrate` uses for a required JSON or enum column). No other stdlib
  module exports those names, so they break no existing program.
- `Std.Codec` gains `schemaFitError` and `schemaValueError` (they compare two
  `jsonSchema` schemas, and check a JSON value against one, for
  `Std.Db.Store`). No other stdlib module exports those names.
- `Sky.Core.Array` is a new module with Elm's names (`get`, `set`, `push`,
  `map`, `foldl`, …). It breaks no existing program; import it qualified:
  `import Sky.Core.Array as Array exposing (Array)`.
- `Std.Image.Canvas` is a new module whose drawing names (`rect`, `ellipse`,
  `line`, `rgba`, `Fill`, `resize`, `measure`) are also in `Std.Ui`,
  `Std.Ui.Canvas`, `Std.Ui.Chart`, `Std.Css`, `Sky.Core.Process` or
  `Std.Ai.Provider`. It breaks no existing program; import it qualified:
  `import Std.Image.Canvas as Canvas exposing (Paint(..))`.
- `Std.Db.Store` gains query builders named as SQL names them. Eight clash
  with names other modules export: `contains` (`Sky.Core.String`,
  `Sky.Core.Regex`), `startsWith` and `endsWith` (`Sky.Core.String`),
  `select` (`Std.Html`, `Std.Db.Table`), `column` (`Std.Ui`,
  `Std.Ui.Keyed`), `exists` (`Sky.Core.File`), `join` (`Sky.Core.String`,
  `Sky.Core.Path`) and `on` (`Std.Html.Events`). A bare `select` under
  `import Std.Db.Store exposing (..)` and `import Std.Html exposing (..)` is
  `[E1012]`.
  - Before: `import Std.Db.Store exposing (..)` and a bare `select attrs kids`.
  - After: `import Std.Db.Store as Store exposing (Store)` and `Store.select`
    for the query, or narrow one of the two exposing lists. The same fix for
    `Store.join`, `Store.on`, `Store.column` and `Store.exists`.
- `Std.Db.Store.index` (an index over columns) clashes with
  `Sky.Core.Json.Decode.index` and `Std.Db.Table.index` under two
  `exposing (..)` imports. Fix: `Store.index`.
- `Store.Table` has two new fields, `indexes : List Store.IndexSpec` and
  `problems : List String` (the builder problems `pushProject` and
  `dumpSchema` refuse).
  - Before: `{ name = "orders", pk = "id", cols = cols }`.
  - After: `{ name = "orders", pk = "id", cols = cols, indexes = [], problems = [] }`.
    Only a hand-built `Table` needs it; `Store.toTable` and
    `Schema.toProject` fill it.

### Regex takes a compiled Regex

`Sky.Core.Regex` now has a type `Regex`. `Regex.fromString : String -> Result
Error Regex` is the only way to make one, and every other function takes the
compiled value instead of the pattern String. Before, each call compiled the
pattern again, and an invalid pattern silently matched nothing (`False`,
`Nothing`, `[]`, the input unchanged). Now an invalid pattern is an `Err` with
the RE2 error text, and a literal pattern is checked when the program compiles
(`[E2014]`, see `docs/errors/E2014-invalid-regex.md`).

Old code fails to compile with a type error whose hint names this section:
`Regex functions take a compiled Regex since v0.29.0`.

- `Regex.match p s` -> `Regex.contains re s` (`Regex.match` is still there and
  is the same function, but it takes a `Regex` too).
- `Regex.find p s`, `findAll`, `findMatch`, `findAllMatches`, `split` ->
  the same name with a `Regex` first.
- `Regex.replace p replacement s`, `Regex.replaceWith p f s` -> the same with a
  `Regex` first.

Before:

```elm
import Sky.Core.Regex as Regex

isCode : String -> Bool
isCode s =
    Regex.match "^[A-Z]{3}-\\d{4}$" s
```

After: compile the pattern once, at the top level, and use the value:

```elm
import Sky.Core.Regex as Regex exposing (Regex)

codeRe : Regex
codeRe =
    Regex.fromString """^[A-Z]{3}-\d{4}$"""
        |> Result.withDefault Regex.never

isCode : String -> Bool
isCode s =
    Regex.contains codeRe s
```

A literal pattern is checked when the program compiles, so
`Result.withDefault Regex.never` never gives `never` for it. For a pattern that
comes from outside (a setting, a user's search), handle the `Err`:

```elm
search : String -> List String -> Result Error (List String)
search pattern lines =
    Regex.fromString pattern
        |> Result.map (\re -> List.filter (Regex.contains re) lines)
```

Writing patterns: a triple-quoted string keeps a backslash (`"""\d+"""` is
`\d+`; a plain string needs `"\\d+"`). Inside one, `\\` is one backslash
(`"""\\d"""` is also `\d`) and `{{` opens an interpolation, so a literal `{{`
is written `\{{`. A single `{` (`\d{2,4}`) is kept. A `Regex` cannot be stored
with a `Codec` or in a session: store the pattern.

`import Sky.Core.Regex exposing (..)` now also exposes `contains` and
`fromString`. Beside `Sky.Core.String exposing (..)` (`contains`), or
`Sky.Core.Bytes`, `Sky.Core.Secret`, `Std.Decimal` or `Std.Money` with
`exposing (..)` (`fromString`), a bare use is `[E1012]`: qualify it
(`Regex.contains`, `String.contains`).

### Std.Image.Format has two more constructors

- `Std.Image.Format` gains `Gif` and `WebpLossless`. A `case` on a `Format`
  that lists every constructor and has no `_` branch no longer covers every
  case and fails to compile with a missing-pattern error that names them.
  - Before: `Jpeg _ -> ".jpg"`, `Png -> ".png"`, `Preserve -> ""`.
  - After: add `Gif -> ".gif"` and `WebpLossless -> ".webp"`, or a `_`
    branch.

### A value defined in terms of itself

- A cycle of values is `[E1018]` BAD RECURSION. It used to pass `sky check`,
  then deadlock on the first read (top level) or fail `go build` (inside a
  `let`), so no working program is affected. The error names the cycle. See
  `docs/errors/E1018-value-cycle.md`.
  - Before: `a = b + 1` and `b = a * 2`.
  - After: give one of them a base value (`b = 2`), or a parameter when it
    really is a loop (`next _ = …`, called as `next ()`).

## Loud at run time (compiles, then stops with an error)

### Std.Db.Store checks names before any statement

Each item below is now `Err (InvalidInput …)` with a message that names the
bad name. No statement reaches the database.

- `findBy` and `delete` with a column that is not in the codec.
  - Before: `Store.findBy conn users "id = id OR 1" "x"` ran and returned a row.
  - After: use a codec column (the field or its snake name):
    `Store.findBy conn users "id" "u1"`.
- A table name outside `[A-Za-z_][A-Za-z0-9_]*` or longer than 63 bytes, on
  every verb. Fix: name the table with letters, digits and `_`.
- A `primaryKey`, `serial`, `unique`, `default*`, `touchOnUpdate`,
  `defaultWith` or `generated` that names an unknown column. Before, the
  builder was ignored. Fix: correct the name.
- `Store.limit n` or `Store.offset n` with `n` below zero. Before, SQLite read
  a negative limit as "no limit". Fix: pass zero or more.
- `defaultNow` or `touchOnUpdate` on a column that is not text, `uniqueOn`
  on a `Maybe` column, `defaultFloat` with NaN or Infinity, and
  `uniqueWhere` with a condition it cannot write as constants (a text match,
  a subquery). Each fails the first verb on the store. Before, `defaultNow` on
  an `Int` column never decoded on SQLite and failed `CREATE TABLE` on
  PostgreSQL. Fix: a `String` field for a timestamp, a required field (or
  `uniqueWhere … (Store.notNull "col")`) for a unique key.
- `Store.migrate` adding a required `unique` column to a table that has
  rows. Every row would get the same default, so the unique index cannot
  hold. Fix: add the column as a `Maybe` field, fill it, then make it
  required in a later release; or add it to an empty table.
- `Store.pushProject` and `Store.dumpSchema` (so `sky db push` and `sky db
  migrate --gen`) with a store whose builder named an unknown column (for
  example `Store.uniqueOn [ "emial" ]`). Before, `sky db push` created the
  table and then failed on the index with a driver error, and `--gen` wrote
  the index into a migration file. Fix: correct the name.
- `sky db migrate` of a `--gen` file that adds a required `unique` column to
  a table with 2 or more rows. It failed before too (the unique index cannot
  hold one default on every row), with the raw database error. Now the error
  names the table, the column and the fix, and the migration still rolls
  back. Fix: in the migration file, add a `{"kind": "raw", "sql": "UPDATE t
  SET c = …"}` op between the `addColumn` and the `addIndex` op that gives
  each row its own value, or make the field a `Maybe`.
- A row error after the first row (`Db.query` and every Store reader). Before,
  the rows read up to the error came back as `Ok`. A query over a column with
  malformed JSON, for example, now fails: repair the row.

### Std.Db.Store checks value kinds before any statement

A value of the wrong kind for its column used to reach the database, which
converted it with no error (SQLite's `CAST('abc' AS BIGINT)` is 0, a `2.7` in
an integer column truncated on SQLite and rounded on PostgreSQL), or reached
the decoder, which read it as `Nothing`. Each item below is now an `Err` that
names the column, the kind and the value. The rule is in
`docs/skydb/overview.md` ("Value kinds").

- A written value of the wrong kind: `updateFields`, `setFields`,
  `setValue`, `setWhen`, `otherwise`, `const`, a `defaultWith` result.
  - Before: `Store.updateFields conn items cond [ ( "qty", SqlString "5" ) ]`
    ran. After: `[ ( "qty", SqlInt 5 ) ]`.
  - `SqlFloat` into an `Int` column: round or truncate in Sky first
    (`SqlInt (round x)`). `SqlInt` into a `Float` column still works.
  - `SqlNull` into a required (non-`Maybe`) column: pass a value, or make the
    field a `Maybe`.
  - A name that is not one of an enum field's names, or JSON its codec does
    not read in a JSON column (a list, record or custom type field): write
    the codec's own encoding, `SqlString (Codec.toJson tagsCodec tags)`.
  - `SqlBytes`, `SqlTime`, `SqlDecimal` and `SqlMoney`: bind the text the
    codec stores, `SqlString (Decimal.toString d)`.
  - NaN or Infinity: check the value first.
- A compared value of the wrong kind (`eq`, `neq`, `gt`, `gte`, `lt`, `lte`,
  `inList`, a `uniqueWhere` predicate).
  - A `SqlString` on an `Int`, `Float` or `Bool` column is read as the
    column's kind, as before on both engines, so `Store.eq "id" (SqlString
    idFromUrl)` keeps working. Text that is not a value of the kind (`"abc"`
    for an `Int` column) is now an `Err` on SQLite too (it matched no row
    there and failed on PostgreSQL). `findBy` and `delete` follow the same
    rule. Fix: check the text first, or match the `Err`.
  - `SqlNull`: it never matched a row on either engine. Use `Store.isNull`
    or `Store.notNull`.
  - Any other kind (`SqlInt` on a text column, `SqlFloat` on an `Int`
    column): pass the column's kind.
- A declared default that does not fit its column, at the first verb on the
  store (`defaultText` on an `Int` or `Bool` column, a `defaultText` that is
  not one of an enum's names or not JSON its codec reads, `defaultInt` on a
  `Bool` or text column, `defaultFloat` on an `Int` column, `defaultBool` on
  anything but a `Bool` column). `migrate` writes the default into the rows
  that exist, so they read back wrong. A `Schema.Table` default
  (`Schema.createTable`, `createSchema`, `toProject`) and an `addColumn` op in
  a migration file follow the same rule. Fix: the default of the column's
  kind (`defaultBool "active" True`, not `defaultInt "active" 1`).
- `adjust` on a nullable or a non-numeric column (NULL plus a delta stayed
  NULL with the row counted as changed). Fix: a required `Int` or `Float`
  field.
- `select`, `selectAs`, `selectColumn`, an `Agg` (`key`, `minAs`, `maxAs`),
  a `copyInto` `from` column and `setCol` whose field codec would read the
  source as `Nothing` (a `List Int` column into a `Maybe (List String)`
  field, a `String` column into a `Maybe` enum field). These verbs are new in
  v0.29.0.
- A stored value that does not read as its column's kind (`'abc'` in an
  integer column, text that is not JSON in a JSON column, `2` in a bool
  column). Before, the row read that field as `Nothing` (or failed to decode
  a required field with a less useful message). Now the read is an `Err`
  naming the table, the column and the kind. The shapes earlier versions
  wrote still read (an integer stored as text, `1` / `0` bools, timestamps).
  Fix: repair the rows. The same holds for a stored value that a `Maybe`
  field's codec does not read (JSON of another shape in a custom type
  column, a projection into a field of another type), at any depth: an
  element of a `List (Maybe Shade)` inside a JSON column that is not a
  `Shade` used to read as `Nothing`, and is now an `Err` naming the table and
  the column (`column "palettes.xs" holds a value its field's codec does not
  read`). A JSON `null` element still reads as `Nothing`. `setValue` of such
  JSON is refused before the statement.
- `selectRaw` with a query that leaves out a codec column. Before, a `Maybe`
  field read `Nothing`. Fix: select it, or `NULL AS col`.

### Codec.maybe reads only null as Nothing

`Codec.maybe c` decoded any value `c` could not read as `Nothing`, so a
mistyped value disappeared with no error: `"x"` in a `Maybe Int` field, a name
that is not one of an enum's, an element of a `List (Maybe a)` of the wrong
shape. Now only JSON `null` is `Nothing`. Any other value must decode as the
inner value, and one that does not makes the whole decode an `Err` that names
where it failed (`at .note: expected Int, got String`). This holds for
`Codec.fromJson`, `Codec.fromJsonSafe`, `Codec.fromXml`, `Std.Db.Store` reads,
Sky.Spa wire decoding and every other use of the codec.

- What does not change: `null` is `Nothing`, `Just x` round-trips, extra keys
  are ignored, and a `Codec.object` field must be present in the object (it
  was already required, a `Maybe` field included). `Codec.auto` already read
  `Maybe` fields this way (and lets a `Maybe` field be absent). Values a
  codec wrote itself always read back.
- Who sees it: a `Codec.fromJson` of JSON from a third party that puts a
  value of another type where the codec expects a `Maybe` (`""` or `"n/a"`
  for a missing number, `0` for a missing string). Before, that field was
  `Nothing`. Now the decode is an `Err`.
- Fix: repair the input, or, where a lenient read is what you want, read
  that payload with `Sky.Core.Json.Decode` and `Decode.maybe` (any failure
  is `Nothing`, as in Elm).
- The `Error` wire codec (`Codec.error`) keeps its forward compatibility: a
  details variant a later release adds still reads as no details. A known
  variant with a bad payload, and a domain-failure key that is there with
  the wrong type (`"retryAfterMs": "soon"`), are now an `Err` instead of no
  details or no delay.

### Std.Image refuses images over its decode limits

- **What happens.** Every `Std.Image` and `Std.Image.Canvas` function that
  decodes reads the image header first and refuses, before it decodes
  anything, an image over 100 megapixels (width x height), a GIF of more than
  1,000 frames, or a GIF of more than 250 million pixels over all its frames
  (width x height x frames). The `Task` fails with `InvalidInput` in the
  domain `"image"`, code `too_many_pixels`, `too_many_frames` or
  `too_many_frame_pixels`, with the attributes `limit` and `value`, and the
  message names the limit. In v0.28 such an image was decoded in full
  (400 MB and more of memory): a tiny file that claims a huge size could take
  the server down.
- **Who is affected.** Apps that process camera images above 100 megapixels
  (some phones take 108 or 200 megapixel photos), or long animated GIFs.
- **What to do.** Check before you process, and tell the user:

  ```elm
  Image.dimensions upload
      |> Task.andThen
          (\d ->
              if d.width * d.height > 100000000 then
                  Task.fail (Error.invalidInput "the photo is too large")

              else
                  Image.resizeToFit (Image.Jpeg 85) 1600 1600 upload
          )
  ```

  `Image.dimensions` and `Image.frames` read the header only and never
  refuse. `Image.reduceFrames` makes a long GIF fit the frame limits only
  when its file is already under them; resize a very long animation before
  upload.


## Silent (compiles, behaves differently)

### Sky.Live sessions start fresh

- **What happens.** A `Dict` (and a `Set`) is now a persistent value,
  `rt.SkyDict[V]`, with a new stored form. A Sky.Live session kept in a
  SQLite, PostgreSQL or Redis session store by v0.28 whose model holds a
  `Dict` cannot be read by v0.29.0 (a `Set` could not be stored before
  v0.29.0, so no stored session holds one). The session is dropped whole:
  the runtime logs one line per session, for example
  `[sky.live] postgres: failed to decode session <id>: the stored session was
  written by an older Sky and holds a Dict or a Set, whose stored form
  changed in v0.29.0; it is dropped and the visitor starts a new session`,
  and the request is served as a new session (`init`). There is no panic and
  no half-read model.
- **Who is affected.** Apps with a persistent session store (`[live] store` /
  `SKY_LIVE_STORE` = `sqlite`, `postgres` or `redis`) whose `Model` holds a
  `Dict`, once, on the first request of each such session after
  the upgrade. Not affected: the memory store (it does not survive a restart
  anyway), a model without a `Dict`, and `App.withDurable`
  snapshots (they are JSON, and a Dict writes the same JSON as before).
- **What to do.** Nothing in code. A visitor with such a session sees a
  fresh page once after the deploy (signed-in state that lives only in the
  model is lost with it). To avoid surprise, deploy at a quiet time or tell
  users. To clear the old rows yourself, delete them from `sky_sessions`
  before the deploy.

### Std.Image Preserve keeps a GIF a GIF

- **What happens.** `Image.Preserve` used to write a GIF as a PNG of its
  first frame. It now writes a GIF, and an animated GIF keeps every frame,
  each frame's delay and disposal and the loop count (comments and other
  extensions are dropped). A WebP under `Preserve` is a lossless WebP (WebP
  input was refused before). `toAlpha` and `whiteToAlpha` of an animated GIF
  give an animated GIF (one-bit transparency); of any other image, PNG as
  before. `Jpeg` and `Png` outputs of a GIF are unchanged: its first frame.
- **Who is affected.** Code that passes `Preserve` and then saves or serves
  the result as `.png` or `image/png` whatever the input was.
- **What to do.** To keep the old output, pass `Image.Png` instead of
  `Image.Preserve`. Or keep `Preserve` and take the extension from the input
  (check the first bytes: `GIF8` is a GIF).

### Std.Db.Store

- **PostgreSQL sorts NULLs like SQLite.** An order term on a nullable column
  renders `NULLS FIRST` for `orderAsc` and `NULLS LAST` for `orderDesc`, on
  both dialects. On PostgreSQL a NULL used to come last ascending and first
  descending. To keep the old PostgreSQL order, sort on a required column, or
  write the query with `Store.selectRaw`.
- **`Codec.autoCamel` stores read correctly on PostgreSQL.** A camelCase
  column used to read as NULL (a `Maybe` field was `Nothing`), and the second
  `Store.migrate` failed. Both work now; nothing to change.
- **A `defaultText` value keeps its meaning.** A value with `|`, `%` or the
  text `touch` (`"untouched"`) is stored as written. Before, `"untouched"`
  made `Store.update` write the clock into the column, `"a|u"` made it
  UNIQUE, and `"a|b%c"` stored `'a'`. A table created before v0.29.0 keeps
  the DDL it was created with: if `Store.create` / `migrate` made a column
  UNIQUE or gave it a cut default this way, fix it by hand
  (`DROP INDEX` / `ALTER TABLE … ALTER COLUMN … SET DEFAULT …`).

- **A nested `Maybe` scalar column made by v0.28 stays TEXT, and keeps
  working.** v0.28 created the column of a `Codec.object` field
  `Codec.maybe (Codec.maybe Codec.int)` (also `Codec.float`, `Codec.bool`)
  as TEXT on both engines and wrote the value as text (`'5'`). v0.29 binds
  the value as a number, and `migrate` never alters a column. Writes into
  the TEXT column work on both engines (PostgreSQL now binds a number into a
  TEXT parameter as its text, as SQLite does), reads parse the text, and an
  `eq` matches. An ordering condition or sort (`gt`, `lt`, `orderAsc`) on
  that column compares text (`'10' < '9'`), as it did in v0.28. To get the
  column type a fresh table has, convert it once by hand. PostgreSQL:
  `ALTER TABLE t ALTER COLUMN c TYPE BIGINT USING c::bigint` for an `Int`
  (`DOUBLE PRECISION` with `c::double precision` for a `Float`, `BOOLEAN`
  with `c::boolean` for a `Bool`). SQLite: create the table again with the
  column `INTEGER` (`REAL` for a `Float`), copy the rows with
  `INSERT INTO new SELECT … FROM old` (for a `Bool`, select
  `CASE c WHEN 'true' THEN 1 WHEN 'false' THEN 0 ELSE c END`), drop the old
  table and rename the new one.

### Std.Db.Store migrate: one rule for both paths

`Store.migrate` (and `sky db push`) and `sky db migrate --gen` now follow the
user's rule D1: "A `Maybe` field gives a nullable column, any other field
gives NOT NULL. A declared builder default wins (`defaultInt` /
`defaultText` / `defaultBool` / `defaultNow`, plus a new `defaultFloat`),
else the zero value of the type. Existing columns are never altered. No
builder makes a required field's column nullable."

What changes for an existing app on its next migrate:

- **Existing columns are not altered.** Nothing is dropped, renamed, retyped
  or made NOT NULL. A column that an older `Store.migrate` added nullable
  for a required field stays nullable, and reads decode as before.
- **A column the app adds from now on** is `NOT NULL DEFAULT <d>` for a
  required field (before: nullable, and a declared default was ignored).
  `<d>` is the declared default, else the zero value: `0`, `''` or false.
  Each column takes its OWN field's zero (`Codec.fieldZeros`). For a
  required JSON (blob) field it is the JSON of that field's zero (its value
  in the blank record you pass to `Codec.auto`, or its codec's zero in a
  `Codec.object` codec), so `tags = []` in the blank gives `DEFAULT '[]'`,
  and a `Codec.list` field gives `DEFAULT '[]'` even beside a `taggedUnion`
  field. For a required enum field (a `Codec.enum` field, or a nullary
  custom type under `Codec.auto`) it is the first name of the `Codec.enum`,
  or the witness's constructor name, because `''` is not one of its names.
  A plain String field keeps `''`. A `Maybe` field stays nullable and now
  keeps its declared default.
- **A required JSON field with no zero value** (a `taggedUnion`, `result`
  or `Codec.error` field of a hand-built `Codec.object` codec, an object
  field holding one, a `Schema.blob` column) is added `NOT NULL` with no
  default. An empty table takes it. On
  a table with 1 or more rows `Store.migrate` is `Err` and a `sky db
  migrate` file fails and rolls back, both with the fix: make the field a
  `Maybe`, derive the codec with `Codec.auto`, or add a data step. Before
  v0.29.0 such a column was added nullable.
- **A `defaultNow` column added on SQLite** holds the time of the ALTER in
  the rows that exist. New rows take the app clock at `insert` /
  `insertMany` / `upsert` (on SQLite only; on PostgreSQL the database
  stamps them, as before).
- **Declared indexes are created** by `create` and `migrate`
  (`Store.index` / `uniqueOn` / `uniqueWhere`, and a `Schema.withIndex`
  through `toProject` for `sky db push`). `migrate` never drops an index.
- **A new table makes a text primary key NOT NULL** (SQLite accepted a NULL
  key before). A table that exists keeps its DDL.
- **Migration files.** `--gen` keeps a declared default (it wrote the zero
  before), keeps a default on a nullable column, splits a unique added column
  into `addColumn` + `addIndex`, and writes `addIndex` / `dropIndex` for
  declared indexes. How the ledger treats files that are already applied is
  in the next section.
- **To make an old nullable leftover NOT NULL** (PostgreSQL), in a migration:
  `UPDATE t SET c = 0 WHERE c IS NULL; ALTER TABLE t ALTER COLUMN c SET NOT NULL`.
  On SQLite leave the column as it is: reads decode as before.
- **`Std.Db.Schema`: `defaultNow` on a `timestamp` / `bigInt` / `int`
  column** now gives epoch milliseconds in a new table (it failed on
  PostgreSQL and stored text on SQLite). A table that exists keeps its DDL.

### sky db migrate: one rule for every migration file

`sky db migrate` (and `SKY_DB_OP=migrate ./app`) renders every migration
file in `db/migrations/` with the rule above, old files and new files alike.
There is no op version and no header line. The `_sky_migrations` ledger now
keeps, for a migration file, a checksum of its **ops** (the op list in a
canonical form, the same on SQLite and PostgreSQL), not a checksum of the SQL
they render to. It also has a new column, `kind`: `ops` for a migration file,
`sql` for hand-written `Db.migrate` SQL. Hand-written SQL keeps the checksum
of its text, as before.

What changes for an existing app:

1. **Applied files are re-stamped once, automatically.** On the first
   `sky db migrate` with v0.29, the runtime adds the `kind` column to
   `_sky_migrations` and gives each applied migration file its ops checksum.
   It logs one info line per file: `db.migrate: migration '<id>' re-stamped
   from the v0.28 checksum to its ops checksum`. Nothing in your schema
   changes. There is no configuration and no command to run. Before that
   first migrate, `sky db status` shows these files as applied.
2. **A file applied by v0.29 is checked by its ops.** A later change to how
   an op renders to SQL never makes it look edited. An edit to the file
   itself still fails with "checksum mismatch", as before.
3. **A pending file written by v0.28 applies with the new rule.** A required
   field gives a `NOT NULL` column with its declared default, else the zero
   value. A required unique column on a table with 2 or more rows fails, and
   the migration rolls back with a message that names the table, the column
   and the fix.
4. **The same file can give a different column in two environments.** A
   pending v0.28 file that adds a required field gives a nullable column if
   v0.28 applies it, and a `NOT NULL` column if v0.29 applies it. Existing
   columns are never altered. If that difference matters to you, apply the
   pending migrations in every environment before you upgrade.
5. **Downgrade to v0.28 is not supported after a v0.29 migrate.** v0.28
   reads the new checksums as a mismatch and stops.

### Std.Db.Store insertMany and upsert compute defaultWith

- `insertMany` and `upsert` left a `defaultWith` column out of the INSERT,
  so the row took the column's database default or NULL (and `insertMany`'s
  doc asked for the value in the records, which were not written either).
  Both now compute it for each row, as `insert` does. An `upsert` that
  updates an existing row keeps the value the row holds.

### Other silent changes

- **Go code must not change a list it is given.** `x :: xs` is now amortised
  O(1): a list built by cons shares its memory with every older list it was
  built on. A Go function reached through FFI that sorts or writes a slice
  argument in place (`sort.Strings(names)`) now also changes those older
  lists. Copy first: `sorted := slices.Clone(names); sort.Strings(sorted)`.
  The rule is in `docs/ffi/boundary-philosophy.md`. Sky code cannot observe
  the sharing: Sky lists stay immutable values.
- **An old list keeps its block alive.** A short list kept for a long time (in
  a Sky.Live model, say) that was the tail of a large accumulator keeps the
  accumulator's memory alive. If a model holds such a tail, rebuild it
  (`List.map identity tail`) before you store it.
- **String kernels keep invalid UTF-8 bytes.** `String.slice`, `left`,
  `right`, `dropLeft` and `dropRight` return a substring of the input. An
  invalid UTF-8 byte inside the result is kept as it was; before, the rune
  round trip replaced it with U+FFFD. Valid text gives the same bytes as
  before, and every index still counts code points.
