# Upgrading from v0.30 to v0.31.0

This page lists every change in v0.31.0 that can affect code or a deploy that
worked on v0.30.0. Each entry says what changed, the old code, and the new
code.

- **Loud** changes stop the build. The error names the change.
- **Loud at run time** changes compile, and the program then returns an `Err`
  that names the change.
- **Silent** changes compile, but the program behaves differently.

The full story of each change is in `CHANGELOG.md` under v0.31.0.

## Loud (fails to compile, the error shows the fix)

### New stdlib names

A bare name that two `exposing (..)` imports now both export is `[E1012]`
ambiguous, and the error names both modules. The fix is the qualified name,
or a narrower exposing list.

| New name | Module | Write |
|---|---|---|
| `dict`, `lazy` | `Json.Decode`, `Json.Encode`, `Std.Codec` | `Decode.dict`, `Codec.lazy` |
| `char` | `Std.Codec` | `Codec.char` |
| `Compatible`, `Earlier`, `Later`, `Reject` | `Std.Time` | `Time.Compatible` |
| `Parts`, `zones` | `Std.Time` | `Time.Parts`, `Time.zones` |
| `withDocument` | `Std.App`, `Std.Live`, `Std.Spa` | `App.withDocument` |

The new modules `Std.I18n`, `Std.I18n.Format` and `Std.Html.Document` share
some names with older modules (`decimal`, `money`, `key`, `language`,
`script`, `document`, `Medium`, `Other`, `lang`, `dir`, `class`,
`translate`). No program that compiled on v0.30 imports them. Import them
qualified:

```elm
import Std.I18n as I18n exposing (Locale, Text)
import Std.I18n.Format as Format
import Std.Html.Document as Document
```

## Loud at run time (an `Err` that names the change)

### `Time.fromParts` refuses dates and local times that are not valid

`fromParts` returns `Err` (domain `"time"`) in three new cases:

- A date that is not in the calendar, such as 31 April or 29 February in a
  common year (code `InvalidDate`). Before, the date rolled over: `fromParts
  "UTC" 2026 2 31 0 0 0 0` gave 3 March.
- A local time that the clocks skip when they go forward (code
  `NonexistentLocalTime`).
- A local time that occurs two times when the clocks go back (code
  `AmbiguousLocalTime`). The error gives both instants.

Old code:

```elm
Time.fromParts "Europe/London" 2026 3 29 1 30 0 0
```

New code, to keep an `Ok` for a skipped or repeated time:

```elm
Time.fromPartsWith Time.Compatible "Europe/London" 2026 3 29 1 30 0 0
```

`Compatible` moves a skipped time forward by the size of the gap and takes
the earlier instant of a repeated time, as JavaScript Temporal does.
`Earlier` and `Later` pick one instant. `Reject` is what `fromParts` does.
An invalid date stays an `Err` with every choice.

### Zone names are exact, and `"Local"` is refused

A zone name in the wrong case (`"europe/london"`) is now `Err` with the code
`UnknownZone`, and so is `"Local"`. Write the exact IANA name
(`"Europe/London"`). Use `Time.isZone` to check a name from a user, and
`Time.zones` to list the names.

### A JSON key two times in one object is refused

JSON text that repeats a key in one object is now an error in every decoder:
`Json.Decode`, `Codec.fromJson`, `Codec.auto`, Sky.Spa messages and
`Std.Db.Store` JSON columns. The error names the key and its path.
`Json.Decode.decodeValue` also refuses an `Encode.object` that gives a key
two times. Before, the last value was kept with no error.

Fix the producer so that it writes each key once. Do not remove keys before
you decode.

## Silent (compiles, behaves differently)

### `Codec.dict` writes a JSON object

`Codec.dict` with a scalar key codec (`Codec.string`, `Codec.int`,
`Codec.float`, `Codec.bool`, `Codec.char`, `Codec.enum`) now writes a JSON
object:

```text
v0.30: [["alice",3],["bob",5]]
v0.31: {"alice":3,"bob":5}
```

The object is byte for byte the JSON that `Codec.auto` writes for a record
field of the same `Dict` type. The member name is the key as text: a
`String` as it is, an `Int` in decimal, a `Float` in its shortest form, a
`Bool` as `"true"` or `"false"`, a `Char` as its code point, an enum value
as its name.

- Sky reads the old pairs array, so rows, files and saved sessions from
  v0.30 still read. A row is written in the new form the next time the app
  writes it.
- A reader outside Sky (another service, a report query, a JavaScript
  client) must read the object.
- `sky db check` can report that the default of an existing required
  `Codec.dict` column is `'[]'` where the code now gives `'{}'`. Both values
  read.

### `-0` and `0` are one `Dict Float` key

A `Dict Float` that held entries under both `-0.0` and `0.0` now holds one
entry, the one inserted last.

### The page language belongs on `<html>`

This is not a change to old code, but an app that set `lang` or `dir` on its
root view element should move them. Screen readers, browser translation and
`:lang()` CSS read them from the root `<html>` element only.

```elm
app =
    App.app { init = init, update = update, view = view, subscriptions = subscriptions }
        |> App.withNotFound NotFound
        |> App.withDocument (\model -> I18n.document model.locale)
```

A Sky.Spa page with no `lang` keeps `lang="en"`. An app with no
`withDocument` renders as before.
