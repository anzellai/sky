`-m=2`: 192,483 inlining calls in package main. The top callees are reflect and
abi internals (abi.(*Type).Kind 15,723, reflect.flag.kind 15,707,
abi.NoEscape 15,237, reflect.Value.Interface 12,447, reflect.toType 11,138, …),
all inlined into the rt.Coerce / rt.coerceInner instances.

Cause: Go compiles a generic function once per type shape, in the package that
instantiates it. Every Sky record alias is its own shape (field names and
`sky:` tags are part of the struct). The client narrows each RPC response to
its own record, so `main` compiled the whole reflect fallback of rt.Coerce,
rt.coerceInner and rt.makeFuncAdapter once per response type: 82 % of SSA time.
The giant Main_view / Main_update / init bodies are linear and are not the
dominant cost.

1,114 MB, 13,124 funcs. Only 103 rt.Coerce instances (0.21 s SSA); the
largest cost is Main_view (0.65 s SSA, the first-paint render). The class is
frontend-specific in size.

bench-gen app (xtask bench-gen, fields 200, arms 200, modules 8): the class is
present but smaller, because the bench app shares response shapes. See §4.

## 2. Fix

runtime-go/rt/rt.go: rt.Coerce, rt.coerceInner, rt.ResultCoerce and
rt.MaybeCoerce are thin generic shells. Only the `v.(T)` fast path and the
final assertion to T are generic. The reflect work is in non-generic functions
compiled once in rt: coerceHead, coerceTail (Coerce), coerceInnerSlow,
reflectResultFields, reflectMaybeFields. The target crosses as `any(zero T)`,
so every reflect.TypeOf and interface check reads what the generic body read.
Results, TypeAssertionErrors and panic messages are the same. No lowering or
codegen change: emitted Go is unchanged, so rt.Coerce counts cannot move.

After the fix (frontend, N=200, `-c=1 -d=ssa/all/time`, 2.57 s in total):

| class | SSA time | funcs |
|---|---|---|
| Main_update | 0.44 s | 808 |
| Main_view | 0.41 s | 601 |
| rt.ResultCoerce instances | 0.23 s | 407 |
| rt.Coerce instances | 0.23 s | 841 |
| rt.ResultCoerceOk instances | 0.19 s | 810 |
| init.N | 0.16 s | 1,454 |
| rt.coerceInner instances | 0.06 s | 408 |

`-bench` -c=8: parse 0.57 s, inline 0.38 s (was 2.88 s), escapes 0.12 s,
compilefuncs 2.05 s (was 7.92 s), 19,753 funcs (makeFuncAdapter instances
gone). `-m=2`: 21,650 inlining calls (was 192,483).

No class dominates now. Main_update (0.39 s alone) and Main_view (0.33 s alone)
are single functions compiled in parallel with everything else at -c=8, and
the compile phase takes 2.05 s wall, so splitting them would save at most a few
tenths of a second. It would also rename the closures that
`handlerIdentity` (rt/live_core.go) reports through FuncForPC. I did not split
them (see "Not done").
