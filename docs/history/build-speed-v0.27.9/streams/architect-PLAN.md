## Corrections to REPORT.md
1. gzip ‖ brotli per asset already parallel (sky/src/main.rs:5234-5253); a content-addressed brotli cache exists (sky/src/precompress.rs:66-120). 2. Inside one `go build`, package main always compiles alone (every other package is its dependency). Capping -p protects no memory within a leg; it only serialises dependencies. Memory can only clash between two concurrent legs.

Field note: 33k lines = 94 s, but a medium private app = 25-38 min, so something is super-linear (-p 1 ratchet, huge main SSA, cold caches, memory thrash). Phase 1 adds per-stage timings at 25k/50k/100k/200k to find it.

## Phase 2 — split emitted Go into packages
Layout sky-out/sky/: package main = entry module + every module that transitively imports it, func main(), all registration init()s in today's order. One package per other module sky-app/sky/m/<Module_Prefix> (package m_<prefix>): funcs, CAF cells/accessors, type decls (+methods), ctors, nullary vars. Dot imports between module packages (as skyffi dot-imports rt); module-prefixed names already unique so bodies byte-identical; `var SkyPkg_<prefix> struct{}` + `var _ = SkyPkg_<prefix>` against unused-import errors. Unexported cross-package use fails go build loudly. skyffi split per binding file (sky-app/skyffi/<gopkg>). rt not split.
Semantics: registration init()s stay in main in order; moved package-level vars are lazy CAF cells or constant literals (codegen ICE + unit test otherwise); types declared once; __caf and accessor share owner.
