## Tier 2 — `shouldSkipFn` in `src/Sky/Build/FfiGen.hs:500`

This is the Haskell-side codegen filter. Called from one site (`FfiGen.hs:374`):

```haskell
let fns = filter (not . shouldSkipFn) (_pkgFns pkg)
```

The actual skip condition:

```haskell
shouldSkipFn fn =
    let hasGeneric = any (isGenericType . snd) (_fnParams fn)
                  || any (isGenericType . snd) (_fnResults fn)
                  || any (genericHint . snd) (_fnParams fn)
                  || any (genericHint . snd) (_fnResults fn)
        isIdPointer = length (_fnParams fn) == 1
                   && length (_fnResults fn) == 1
                   && isBareParam (snd (head (_fnParams fn)))
                   && isStarBareParam (snd (head (_fnResults fn)))
        refsInternal = any (touchesInternal . snd) (_fnParams fn)
                    || any (touchesInternal . snd) (_fnResults fn)
    in (hasGeneric && not isIdPointer) || refsInternal
```

Three predicates, two reasons to skip:

| Predicate         | Triggers on                                                                                     |
|-------------------|-------------------------------------------------------------------------------------------------|
| `hasGeneric`      | Bare `T` / `[T]` / `[T any]` / `[K ...]` / `[V ...]` / `[]T` / `*T` suffix in any param or result |
| `genericHint`     | Stricter substring catches — `[T `, `[T]`, `[T,`, `[K `, `[V `, `[]T`, bare `T` / `*T` suffix    |
| `isIdPointer`     | Single-param single-result `T -> *T` — Sky's identity-pointer escape hatch                       |
| `refsInternal`    | Touches `/internal.` / `/internal/` / `/vendor.` / `/vendor/` — Go forbids cross-module imports of those |

Skip condition: `(hasGeneric && not isIdPointer) || refsInternal`.

So at Tier 2:

- **Skipped**: generic methods (Stripe `*V2List[T any].Iter()`, `sync.Pool[T].Get()` — Sky's HM has no higher-kinded support per CLAUDE.md Limitation #1).
- **Kept**: `func[T any](t T) *T` and similar identity-pointer shapes — Sky CAN unify these.
- **Skipped**: anything touching `/internal/` or `/vendor/` paths.

### What Tier 2 does NOT skip

The crucial Cause-G families all survive:

- **All setters** (`Set<Field>` / `Set<Var>`) — no skip
- **All getters** — no skip
- **All embedded-interface bridges** (Go's promoted methods) — no skip
- **All hand-coded `Value` sigs** — these aren't in kernel.json at all; they live in `Sky.Type.Constrain.Expression`. Out of scope for both tiers.

## PR-9 risk surface (`types.Implements` false-neg at scale)

Master plan abort trigger #3: *PR-9 reveals Go's `types.Implements` is unreliable for embedded interfaces at Stripe/Fyne scale (false-neg > 5%)*. The current Inspector uses `types.Implements` only at `implementsError` (line 754) against the universe `error` interface — a trivial case.

PR-9 extension will be to iterate every concrete `*types.Named` and probe `types.Implements(named, knownIface)` for each interface declared by other packages in the same load. This is O(N×M) named types × interfaces but should be tractable for the Stripe corpus (76k symbols, ~200 interfaces).

Risk patterns to test for in PR-9:

1. **Embedded interface in a struct**: `type S struct { net.Conn }` — Go reports S implements `net.Conn`. Inspector's `addPointerMethods` already picks up the promoted methods. ✅
2. **Interface with type parameters** (Go 1.18+): `type Sliceable[T any] interface { Slice() []T }`. `types.Implements(*types.Named, *types.Interface)` requires the interface to be fully instantiated. **PR-9 contract:** skip parameterised interfaces analogous to `addZeroConstructor`'s generic-type early-return AND `shouldSkipFn`'s `hasGeneric` filter. Document as a known limitation.
3. **Variadic method signatures**: `func (r *Router) Use(mw ...Middleware)`. `types.Implements` treats these correctly (signatures unify with variadic flag).
4. **Methods with type-parameter receivers**: methods on a generic type's instantiation. Should work; PR-9 will verify.

If PR-9 reveals > 5% false-neg, abort path is documented in master plan: revert to Limitation #11.
