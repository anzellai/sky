# C17 — FFI opaque type distinctness (revised design)

> **Status (2026-06-13):** Original v5 plan framed C17 as a single
> commit ("change `opaqueValue = Can.TType (Canonical "") "Value" []`
> to qualified names"). Adversary RED grill revealed this is
> structurally multi-PR with 4+ downstream consumers. Reframing as
> umbrella with examples/13-skyshop end-to-end as the gate.

## Why the original framing failed

The v5 plan claimed:

> Backwards-compat: opaque types compare equal only when fully
> qualified equal.

Implied a one-line fix at `FfiTypeResolve.hs:106`. Adversary grill
found **5 load-bearing wrong assumptions**:

1. **Inspector doesn't emit qualified names today.** Plan stated it
   did. `tools/sky-ffi-inspect/main.go:442-461` calls
   `tt.String()` for `*types.Named` which produces bare `Customer`,
   not `*github.com/stripe/stripe-go/v84.Customer`. Inspector must
   change FIRST.

2. **4+ downstream `"Value"` sentinel consumers** silently break:
   - `src/Sky/Type/Constrain/Expression.hs:1765, 1769` —
     hand-coded `Context.background` / `Context.todo` sigs
   - `src/Sky/Build/Compile.hs:6750` (`defaultErrorTVars`),
     `:6798` (`defaultOpaqueTVars`) — TVar default policies
   - `src/Sky/Build/Compile.hs:6014, 6027, 6071` — codegen
     `runtimeTypedMap` lookup keyed on bare `"Value"`
   - Side effect: codegen emits `rt.SkyValue` ONLY when name
     matches `"Value"`; under new qualified scheme, emission
     falls through to bare `Customer` (undefined Go)

3. **HM cross-package use is a real pattern**, not a corner case.
   Today `Firestore.newClient (case Context.background () of Ok c -> c)`
   type-checks because both sides see `Value`. C17 as-planned
   makes this E2001:
   ```
   Context.background : () -> Task Error Value     (hand-coded)
   Firestore.newClient : ("context", "Context") -> ... (qualified)
   ```

4. **`.skyi` cache invariants change**. Old `.skyi` files in
   `.skycache/ffi/` carry `Value` strings. Re-parsing under C17's
   new grammar produces different `T.Type` values. Must regen
   every example with FFI usage; `cacheSchemaVersion` invalidates
   lowered Go but NOT `.skyi` (those participate via the kernel.json
   path which is text-stable).

5. **examples/13-skyshop (76k FFI symbols) is the gate**. Stripe
   SDK internally crosses opaque types across customer/checkout/
   subscription/paymentMethod kernels; today they all unify at
   `Value`. C17 surfaces every cross-kernel call as a type error
   UNTIL the qualified canonicals propagate everywhere.

## Revised C17 — 6-commit umbrella

Each commit ships safely; full series gates on skyshop e2e.

### C17a — Inspector qualified opaque emission

**File:** `tools/sky-ffi-inspect/main.go:442-461` (`skyTypeOf`)

Extend `*types.Named` arm to emit a fully-qualified opaque marker
the Sky parser can split. Suggested grammar (back-compat):

- Current: `Customer`
- New: `Customer@github.com/stripe/stripe-go/v84`

`@`-suffix is parser-stable + grep-friendly. Existing parsers that
don't know about it can strip after the `@`.

Verification: regen one example (e.g. `examples/13-skyshop`'s
`.skycache/ffi/stripe.kernel.json`) and grep for `@` separators.

### C17b — FtyAst grammar widening

**File:** `src/Sky/Build/FfiTypeParser.hs`

Extend the `FtyAst` ctor (or add new `FtyOpaque !String !String`
variant) to carry the package path. Update lexer/parser to split
on `@`.

Existing test fixtures: pin to old form for back-compat; add new
fixtures exercising `@`-qualified names.

### C17c — FfiTypeResolve emits qualified canonical

**File:** `src/Sky/Build/FfiTypeResolve.hs:106` (the original
target of v5 C17)

Change `opaqueValue` definition: build
`Can.TType (Canonical pkgPath) typeName []` from the FtyAst.
Consume the `_kernelName` arg that's currently dropped.

`Value` literal stays only at sites that genuinely mean "polymorphic
opaque escape" (TVar defaults). Cause-G surface migrates here.

### C17d — Codegen recognises FFI canonicals as `rt.SkyValue`

**File:** `src/Sky/Build/Compile.hs` (6014, 6027, 6071)

`runtimeTypedMap` / `safeReturnTypeFull` / `safeReturnTypeBootstrap`
add a new arm: if `Can.TType (Canonical home) _ _` AND `home` is
non-empty AND NOT a Sky stdlib/builtin module, treat as opaque FFI
and emit `rt.SkyValue` (preserves Go-side `.(*pkg.X)` routing).

Reuse the existing `qualifiedRuntimeTypedMap` populate path.

### C17e — Hand-coded sigs migrate

**Files:** `src/Sky/Type/Constrain/Expression.hs:1762-1769`,
plus any other `Can.TType (Canonical "") "Value" []` literal use.

Migrate `Context.background` / `Context.todo` and audit Fmt.
Pin each to its canonical Go package import path.

### C17f — examples/13-skyshop regen + cabal sweep + skyshop e2e

**Files:** `examples/13-skyshop/.skycache/ffi/` (regen via
`sky install --force`).

Cabal sweep must pass. skyshop e2e: build, run server, hit endpoints.

Bump `cacheSchemaVersion` constant from `"v0.17.0"` to `"v0.17.1"`
in `src/Sky/Build/Compile.hs:825` to force lowered-Go invalidation
across all examples.
