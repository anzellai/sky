## Empirical answer to the user's question

The on-disk `runtime-go/rt/console_app/main.go` was generated by a
PREVIOUS compiler version.  Since then, a specific commit
**regressed** the codegen for the bundled-console — emitting `any`
where the compiler used to emit typed aliases.

| | On-disk (previous compiler) | Regenerated (current compiler) |
|---|---|---|
| `State_Model_R.Store` | `State_Store_R` (typed) | `rt.SkyStore` (kernel) |
| `State_Model_R.Tab` | `State_Tab` (typed) | `any` |
| `State_Model_R.Range` | `State_Range` (typed) | `any` |
| `chosenStore := func() …` | `State_Store_R` (typed IIFE return) | `any` |
| `Store: …` literal | `rt.Coerce[State_Store_R](chosenStore)` | `any(chosenStore).(rt.SkyStore)` |

**Bundled-console source has NOT changed since the last good
regenerate** (verified via `git log -- sky-bundled/console/src/` —
empty between the last `chore: regenerate console_app` commit and
HEAD).  The compiler regressed.

## The breaking commit

`git bisect` between `ae615ab5` (last known-good regenerate) and HEAD
(53e82c44) — 192 commits — identified:

```
7d09b428a73e5f76b8ea7fd7f389098301ba65be is the first bad commit
commit 7d09b428a73e5f76b8ea7fd7f389098301ba65be
Author: Anzel Lai <anzel.lai@gmail.com>
Date:   Thu Jun 25 18:43:06 2026 +0100

    Fix v0.17 compiler soundness regression in RtFieldAdtBug342
    by threading caller ctx to snapshotCallerCtx
```

942-line refactor in `src/Sky/Build/Compile.hs`.  The specific change
that caused the bundled-console regression:

```haskell
lowerRecordLiteralTo targetTy fields =      -- BEFORE
-       env = getCgEnvFromScope             -- read from IORef
-       fieldCtx = snapshotCallerCtx ()

lowerRecordLiteralTo phaseACtx ctx targetTy fields =  -- AFTER
+       env = lookupCgEnvFromCtx phaseACtx  -- read from threaded ctx
+       fieldCtx = snapshotCallerCtx () ctx -- threaded ctx parameter
```

## Why this change broke bundled-console

The refactor was **architecturally correct** — moving from
IORef-backed reads (`getCgEnvFromScope`) to ctx-threaded reads
(`lookupCgEnvFromCtx phaseACtx`) is the locked Phase A direction
per `docs/v0.17-roadmap/phase-A-cgenv-reshape.md`.

**The regression mechanism**: the live IORef (`scopeStateRef`)
ACCUMULATES alias registrations as dep modules are emitted.  The
threaded `phaseACtx` carries an EARLIER SNAPSHOT taken at compile
entry.  For the bundled-console (which uses multi-module deps where
late-registered aliases are needed by the literal-emit at
lowerRecordLiteralTo), the snapshot is less complete than the live
IORef — so `_cg_recordAliases` doesn't contain `State_Store`,
`State_Tab`, etc. at the time the renderer needs them.

Result: mapNamedType's runtimeHit branch wins for `Store`/`Tab`/
`Range` instead of the record-alias branch.  Output emits kernel
forms (`rt.SkyStore`, `any` for non-record-alias types).

## Why every other example builds clean

The 26 examples in the sweep don't exercise this pattern:
- Most user examples (01-29) are single-module or have simple dep
  structure where the snapshot vs live cgEnv don't diverge at
  literal-emit time.
- Stdlib aliases (Maybe, Result, Task, …) don't collide with user
  alias names.
- The bundled-console uniquely has a multi-module dep structure
  (State, HubStore, Overview, etc.) where State.Store is declared
  in a dep but referenced at literal-emit time when the snapshot
  hasn't yet seen State's registrations.

## The actual fix path

The bisect proves: the bundled-console used to work.  The fix
re-enables that behavior.  Options:

### Option F (revert the snapshot move at this site)

At `lowerRecordLiteralTo`, restore `env = getCgEnvFromScope` (live
IORef read) while keeping the rest of commit 7d09b428's
refactor.  This re-enables the bundled-console regenerate WITHOUT
losing the RtFieldAdtBug342 fix (which lives in a different code
path of the same refactor).

Risk: violates the locked Phase A direction (IORef readers should
be migrated, not re-introduced).  But it's a TRANSITIONAL fix that
ships v0.17 with working bundled-console; the proper Phase A close
replaces the IORef reader with a correctly-populated ctx in a
later release.

### Option G (populate phaseACtx with live IORef contents at lowerRecordLiteralTo entry)

Inside `lowerRecordLiteralTo`, before reading from phaseACtx,
refresh the relevant cgEnv fields from the live IORef.  Surgical;
adds 3-5 lines.  Preserves the ctx-threaded reader interface but
opts into IORef-live-state semantics at this specific site.

### Option H (push snapshot capture later)

Move the `phaseACtx` capture to AFTER all dep emission completes.
Requires changes higher in the compile pipeline.  Larger scope but
the architecturally cleanest fix.

## Recommendation

**Option F** for immediate ship.  Documented as transitional
bridge.  Files the proper close as v0.17.1 Phase A continuation.
1-line code change, restores bundled-console regenerate gate, no
regression risk to other examples (the IORef reader was the
behavior for the entire history before 7d09b428).
