# Dispatch — Layer-2 member H

A note-publishing + notification service. It exists to cover **five stdlib
modules that were imported by nothing in this repo**, and therefore executed by
no test at all:

| Module | What Dispatch exercises |
|---|---|
| `Std.Db.Schema` | typed dialect-safe DDL (`serial` / `notNull` / `unique` / `defaultText` / `defaultInt`) + the `toProject` bridge |
| `Std.Db.Migrate` | the committed `db/migrations/*.json`, applied via `sky db migrate` |
| `Std.Jobs` | `define` / `enqueue` / `enqueueIn` / `cancel`, a real worker, a real failure |
| `Std.Markdown` | `render` into the `Std.Ui` view, including untrusted input |
| `Std.Email` | message composition through the full builder chain |

The consequence of that gap was that **the file-based migration verbs
(`sky db init` / `migrate --gen` / `migrate` / `status` / `seed`) were exercised
by no project**.

## Shape

A Sky.Live app. Pages render `Std.Ui`; `Live.api` routes expose the JSON the
gate asserts on. Sky.Live is also the only app shape whose SIGTERM path calls
`JobsShutdown()` (`runtime-go/rt/live.go`), so it is the shape a jobs-bearing
app should actually take today.

```
src/Schema.sky   Std.Db.Schema tables -> toProject -> `db : Store.Project`
src/Work.sky     Std.Jobs handlers + Std.Email composition
src/Api.sky      the JSON endpoints the harness asserts
src/Main.sky     Live wiring, seed, and the Std.Markdown page
db/migrations/   COMMITTED, generated by `sky db migrate --gen`
```

## Running it

Nothing in `src/` names a driver, a DSN, or a port — all three come from the
environment, which is what lets one source tree run both arms.

```bash
export SKY_DB_PATH=./dispatch.db          # or postgres://u@h:5432/dispatch
export SKY_JOBS_STORE=sqlite
export SKY_JOBS_STORE_PATH="$SKY_DB_PATH" # same database: see below
sky db migrate && sky db seed && sky build src/Main.sky
SKY_LIVE_PORT=8095 ./sky-out/app
```

`SKY_JOBS_STORE_PATH` deliberately points at the **same** database as the app.
That is what makes a job failure assertable from outside the process:
`/api/jobs/failures` reads the queue's own `_sky_jobs` ledger through the app's
connection, so the gate can assert that the runtime *recorded* the failure
(attempts + a readable message) rather than swallowing it.

There is no `[jobs]` section in `sky.toml` on purpose — see the note in that
file. `jobs_kernel.go` refers to one in four comments, but nothing parses it.

## Endpoints

| Route | Verdict it supports |
|---|---|
| `GET /` | the `Std.Markdown` render, including that untrusted markdown is **escaped** |
| `GET /api/health` | which driver actually opened, and the jobs backend in use |
| `GET /api/dispatch/run` | enqueues one delivery per subscriber, one always-failing job, and one delayed job it then cancels |
| `GET /api/deliveries` | what the worker actually **wrote** — the proof a job ran |
| `GET /api/jobs/failures` | the recorded failure: attempts + `last_error` |
| `GET /api/email/preview` | the composed `Std.Email` message |

## What the gate asserts, and why each one bites

- **`sky db status` exits 1 while a migration is pending** and 0 once applied —
  the deploy gate, asserted by exit code rather than by output text.
- **UNIQUE / AUTOINCREMENT / DEFAULT survive the migration.** `sky db migrate`
  once dropped all three where `sky db push` preserved them: duplicate rows
  accepted on SQLite, the app broken on Postgres. It was fixed once and nothing
  gated it, because no project declared constraints through a committed
  migration.
- **A destructive diff is quarantined, not applied** (`apps-dispatch-destructive`):
  dropping a column must produce `"ops": []` and a populated `"destructive"`
  array.
- **A job actually ran** — asserted from the rows the worker wrote, not from
  `enqueue` returning an id, which it does whether or not a worker ever starts.
- **A failing job is observable** — attempts recorded and a *readable*
  `last_error`. Building this app found that field contained
  `{0 Error [7 {the real message <nil>}]}`, a Go struct dump of the Sky Error
  ADT (fixed in `runtime-go/rt/stdlib_extra.go`).
- **Untrusted markdown is escaped** — `<script>` in a note body must come back
  as `&lt;script&gt;`.
- **Dialect parity** — the same source, the same assertions, only the DSN
  changes (`apps-dispatch` on SQLite, `apps-dispatch-postgres` on Postgres).
